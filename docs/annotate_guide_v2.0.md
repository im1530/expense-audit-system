# 单据标注指南 v2.0（blind_v2）

> 版本：`annotate_guide_v2.0` ｜ 适用样本：`blind_v2`（60 条） ｜ 定稿日期：2026-11-14
> 本指南与 `blind_v2.json`、两份盲包一并冻结；**标注开始后不得修改**（要改只能升 v2.1 并重标）。

## 1. 这份工作要回答什么

两个人**不看任何 AI 结论**、各自独立标一遍同一批 60 条单据，然后计算：

- 逐维度百分比一致率；
- Cohen's κ 与 bootstrap 95% 置信区间；
- 分歧项由第三人裁决后的终版标签。

结论用于回答"人工标准本身稳不稳定"，**不用于调 Prompt、不用于改模型**。所以标注时请按制度判断，不要猜系统想要什么答案。

## 2. 你会拿到什么

一份 Excel 工作簿（`blind_v2_packet_A.xlsx` 或 `_B.xlsx`），含三页：

| 页 | 内容 |
|---|---|
| 标注表 | 60 条单据事实 + 待填列 |
| 标注说明 | 本指南的压缩版（风险/决策定义、独立性要求） |
| 制度条款 | 制度 v1.2 全部 33 条原文（引用时查这里） |

**不包含**：AI 预审结论、风险分、规则命中结果、工程标签、另一位标注人的答案、案例原始编号。盲编号（B001–B060）只用于合并结果，不含任何分层信息。

## 3. 怎么标（每条 3 步）

1. **读事实**：标题/费用说明、费用类别、金额、费用发生日期、提交时间、是否有票、无票说明；
2. **对制度**：翻《制度条款》页，看金额是否超限、是否跨期、凭证是否合规、是否重复/拆分/个人消费；
3. **填三列**：`风险等级`（必填，下拉）、`决策建议`（必填，下拉）、`引用条款`（可选），并在`理由`里写一句依据（必填，便于裁决）。

## 4. 风险等级定义

| 等级 | 定义 | 典型情形 |
|---|---|---|
| `low` | 单据事实齐全、票证合规、金额在限额内，无违规特征；或只有不影响真实性的小瑕疵 | 金额低于限额且凭证齐全；说明略简但事实清楚 |
| `mid` | 存在需要人工核实的疑点，但事实本身不足以认定违规 | 缺票/弱凭证、超限、跨期（>60 天）、金额与票面不一致、抬头信息缺失、发票号不一致、日期异常、审批缺失、影像无法识别 |
| `high` | 存在明确违规或舞弊特征 | 虚增/虚报金额、重复报销、同一发票号/订单号重复、个人消费、测试单据、抬头为非公司主体、伪造篡改、拆票规避审批权限 |

判定规则：

- 一条单据命中多个特征时，**取最高档**；
- 不确定时选较高档，并在`理由`写明"不确定原因"（宁可保守，不要猜低）；
- 不因金额小而降档：金额再小，只要是个人消费/测试单据，仍是 `high`；
- 只依据本页事实判断，不假设页面外还有补充材料。

## 5. 决策建议定义

| 决策 | 含义 |
|---|---|
| `fast_track` | 低风险且无中高风险疑点，建议走正常审批、无需额外核查（**不等于自动通过**） |
| `manual_review` | 有疑点需要人工核实（默认档） |
| `suggest_reject` | 明确违规，建议驳回/补正 |

硬边界（与系统决策层口径一致，请严格遵守）：

1. `low` 且无 `mid/high` 疑点 → 才可 `fast_track`；
2. 只要风险是 `mid` → **必须** `manual_review`，不得 `fast_track`；
3. 风险是 `high` → 通常 `suggest_reject`；若你认为需人工核实后再定，可选 `manual_review`，但必须在`理由`写明；
4. 决策只是建议，不代表系统会自动通过、驳回或付款。

## 6. 引用条款（可选，但建议填）

- 填条款号，如 `2.4`、`5.1`；多条用逗号分隔（`2.4,3.7`）；
- 只填与本案事实**直接相关**的条款；不确定就留空，**不得编造编号**；
- 条款原文见工作簿《制度条款》页（制度 v1.2，33 条）。

## 7. 常见边界（示例，供校准口径）

| 事实 | 建议风险 | 建议决策 | 主要依据 |
|---|---|---|---|
| 无票，但填写了无票说明与佐证 | `mid` | `manual_review` | 2.3、2.5：允许无票但需核实 |
| 无票，且无说明、无发票号 | `mid` | `manual_review` | 2.5：凭证缺失需补正 |
| 金额低于限额，凭证齐全、事由清楚 | `low` | `fast_track` | 3.x 限额、2.2 凭证 |
| 超过类别单次限额，但事由合理 | `mid` | `manual_review` | 3.7：超限需说明并核实 |
| 同一发票号/订单号重复出现 | `high` | `suggest_reject` | 1.2、4.3：禁止重复报销 |
| 个人消费（与公务无关） | `high` | `suggest_reject` | 1.2：真实性、相关性 |
| 测试单据/演示单混入报销 | `high` | `suggest_reject` | 1.2：不得虚报 |
| 抬头不是公司全称 | `high` | `suggest_reject` | 2.2：抬头、税号须准确 |
| 费用发生超过 60 天才提交 | `mid` | `manual_review` | 4.2：跨期需说明 |
| 同一事项拆成多张单据 | 视合计金额：`mid` 或 `high` | `manual_review` | 7.2：不得拆分规避权限 |
| 缺少事前审批（超标采购） | `mid` | `manual_review` | 3.7、5.x：按权限审批 |
| 影像无法识别/识别失败 | `mid` | `manual_review` | 2.5：凭证需可核验 |

## 8. 独立性要求（最重要）

- 不看另一位标注人的工作簿，不讨论、不商量、不交换意见；
- 不查看系统里的 AI 预审结论、风险分、规则命中；
- 不查历史报销记录、不询问提交人（本轮只做纸面判断）；
- 两份包在**同一时间窗**内完成（建议 3 个工作日内），各自独立提交；
- 填完只提交，不回改；确需修改时在`备注`写明原因与时间。

## 9. 交付与后续

1. 填完另存为 `blind_v2_packet_A_<姓名>_<日期>.xlsx`（B 同理），交回；
2. 由第三人（或项目负责人）对分歧项裁决，产出 `high_risk_final_v2.json`（含 `adjudicated_by`、`adjudicated_at`）；
3. 报告写三组数字：**原始一致率 / κ 与 95% CI / 裁决后终版标签**；
4. 标注结果不回流到 Prompt 调优，避免污染后续评测。

## 10. 术语

| 术语 | 含义 |
|---|---|
| 盲编号 | `B001`–`B060`，仅用于合并两份结果，与风险高低无关 |
| 单据 | 一条报销单（含 1 条明细） |
| 无票说明 | 报销人填写的"为什么没有发票"的说明与佐证 |
| 跨期 | 费用发生日到提交日超过 60 天 |
