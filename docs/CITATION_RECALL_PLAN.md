## 〇、落地结果（先看结论）

| 项 | 改动前 | 改动后 |
|---|---|---|
| chroma 核心条款检索覆盖（68 条） | 56/68 = **82.4%** | **68/68 = 100%** |
| 未覆盖案例 | G021–24、G045–52 | 无 |
| 单次检索耗时 | — | 4.5 ms（20 次平均） |
| 自检 | ChromaPolicyRetriever / 33 条 | 不变，`degraded=false` |

改动：`app/rag/chroma_retriever.py` 的 `build_embed_text()` —— 参与向量化的文本由"仅条款原文"改为 **"关键词在前 + 原文在后"**；签名加入 `doc=v2_kw_first`，口径变化会**自动重建集合**（否则会出现"改了代码但检索结果不变"）。

为什么是这个口径（离线实测，同一批 68 条）：

| 向量文本 | 覆盖率 | 相关条款占比（top4 中核心∪可选的比例） |
|---|---|---|
| 仅原文 | 82.4% | 32.6% |
| 原文 + 关键词 | 94.1% | 36.5% |
| **关键词 + 原文** | **100%** | **36.5%** |

关键词由人工维护、本就是为检索而写，放进 embedding 后既提高召回也没牺牲相关度（占比反而从 32.6% 升到 36.5%）。最长条款拼装后 172 字符 < `POLICY_EMBEDDING_MAX_LENGTH=256`，不会被截断。

**必须说明的口径变化**：引用准确率/召回率（98.91% / 92.65%）来自旧录制，改动后**已不代表现状**，要更新只能重录（真实调 LLM，96 条约 18 万 input token）。检索层指标已用零成本方式验证。

### 全量重录与"指标噪声"结论（2026-11-11/12）

全量 96 条共跑了 3 次（v4.2 @ temp0.1、v4.2.1 @ temp0.1、v4.2.1 @ temp0），外加 1 次 11 条复现性抽检：

| 指标（96 条标注） | 旧录制 v4.1+BM25 | v4.2 + chroma | v4.2.1 + chroma | v4.2.1 + chroma + temp0 |
|---|---|---|---|---|
| 决策一致率 | 100% | 100% | 100% | 100% |
| 风险一致率 | 100% | 100% | 100% | 100% |
| 高危漏放 | 0 | 0 | 0 | 0 |
| 检索覆盖率 | 98.53% | **100%** | **100%** | **100%** |
| 引用召回率 | 92.65% | 92.65% | 88.24% | 89.71% |
| 引用准确率 | 98.91% | 89.66% | 90.24% | 90.24% |

**关键结论：引用指标存在 ±5pp 的模型噪声，单次运行无法区分 Prompt 版本。**

证据：用**完全相同**的 Prompt 与 `temperature=0` 重跑 11 条，引用结果只有 6/11 一致：

```
G023: []            → ["2.2"]
G049: ["1.2"]       → ["1.2", "4.3"]
G052: ["1.2","4.3"] → ["1.2"]
G093: []            → ["3.4"]
G099: []            → ["7.3"]
```

因此：

- **可以稳定采信的只有检索覆盖率（100%，与模型无关、可重复）**，以及"4 个目标案例在每次运行中都引到了核心条款"；
- 引用召回率在 88%–93% 区间波动，v4.1/v4.2/v4.2.1 之间的差异都在噪声范围内，**不能据此判定谁更好**；
- 若必须要一个可信的引用指标，需固定 Prompt 跑 ≥3 次取中位数（每次约 18 万 input token）。

## 一、先纠正一个前提：现有引用指标是"BM25 时代的录制回放"

`v4_1_100_full96.md` 标注为 **replay 模式**，指标来自历史录制文件，不是当前默认后端（chroma）的实测。

离线复测（同一批 68 条有核心条款的案例，`POLICY_TOP_K=4`，各后端用各自默认阈值）：

| 检索后端 | 核心条款检索覆盖 | 未覆盖案例 |
|---|---|---|
| BM25 | **67/68 = 98.5%** | G032 |
| hybrid（RRF 融合） | **67/68 = 98.5%** | G032 |
| chroma（当前默认） | **56/68 = 82.4%** | G021–G024、G045–G052 |

98.5% 与报告里的「核心条款检索覆盖率 98.53%」完全对上，说明**报告数字对应的是 BM25 记录**。切到 chroma 后覆盖率掉了 16 个百分点，但指标没有重测。

## 二、四个案例的真实成因（逐条定位，均有数据支撑）

### G049 / G052（重复订单号，缺 1.2）

chroma 下 1.2 的排名（查询 = 该案例原文）：

| 条款 | 排名 | 相似度 |
|---|---|---|
| 4.3（同人同日同类别同金额） | 1 | 0.6363 |
| 2.2 | 14 | 0.4654 |
| **1.2（真实性/禁止重复）** | **16** | **0.4615** |

`top_k=4` 只保留前 4，1.2 直接被截断 → 模型只能在 4.3 里选，**不是 Prompt 选择错误，是召回缺失**。
同一现象覆盖 **G045–G052 全部 8 条**。

### G030（金额超额，引 2.2 而非 2.4）

该案例当前 chroma 排名：**2.4 第 1（0.6465）、2.2 第 2（0.6407）**，2.4 明确在上下文里，模型仍引了 2.2。
**这是选择错误（Prompt 问题）**，不是检索问题。

### G032（金额超额，无引用）

chroma 下 **2.4 排名第 1（0.6606）**，当前后端下已可召回；它只在 BM25 下缺失（BM25 漏检清单里就它一条）。
**结论：G032 是 BM25 时代的检索缺口，chroma 已修复。**

### 补充：G021–G024（弱凭证超限，缺 2.2）

三种向量方案都召回不到 2.2（BM25 可以）。属同一类"向量对长条款不敏感"问题，不在本次 4 个案例范围内，但会被同样的方案影响。

## 三、两套方案（均未实施）

### 方案 A：Prompt 约束（v4.2 citation guard）

只针对"检索到了但选错"的情况，改动集中在 `app/agents/prompts.py` 的 `CITATION_GUARD`：

1. **方向禁令（强化现有第 1 条）**：明确"发票金额高于明细"时不得引用 2.2（其原文只约束"不得低于"），应引 2.4 或改 `type=invoice` 不引用；
2. **禁止性条款优先**：事实是"同一发票号/订单号重复"时，必须以 1.2（真实性、禁止重复）为主依据；4.3 仅在"同人同日同类同金额"成立时作可选，不得替代 1.2；
3. 保留第 3 条"先找再弃"，避免为了引用而引用。

| 维度 | 评估 |
|---|---|
| 能修 | G030（选择错误），以及未来同类"方向/主题错配" |
| 不能修 | G049/G052（1.2 根本不在上下文里）；G032 现状已可召回 |
| 代价 | 改 Prompt 文本；**必须重录才能验证**（96 条约 18 万 input token；可先用 `--case-ids G030` 只重录 4 条，成本可忽略） |
| 风险 | 把条款号写死会随制度版本漂移 → 建议写"方向/主题"规则 + 一个具体反例，不写死编号 |

### 方案 B：制度关键词 / 向量文本增强

实测发现：**chroma 只对 `clause.text` 做 embedding，`keywords` 完全不参与向量检索**（`chroma_retriever.py:154`）。所以单纯改制度文件里的 keywords 对当前默认后端**零效果**，只有 BM25 受益。

真正有效的做法是把 keywords 并入向量文本（代码改动 + 重建集合）。离线模拟（同一批 68 条，top4）：

| 向量文本 | 覆盖 | 未覆盖 |
|---|---|---|
| 现状（仅原文） | 82.4% | G021–24、G045–52 |
| **原文 + keywords** | **94.1%** | G021–24 |

| 维度 | 评估 |
|---|---|
| 能修 | G049/G052（1.2 进前 4），以及 G045–G048 同类 8 条中的 8 条 |
| 不能修 | G021–G024（2.2 仍召回不到）；G030（选择错误） |
| 代价 | 改 `chroma_retriever.py` 写入逻辑 + 重建集合（`policy_version`/条数不变不会自动重建，需显式触发）；离线即可验证覆盖率，不花钱 |
| 风险 | 关键词若有噪声会挤掉原本正确的条款 → 必须用 68 条覆盖率回归对比 |

### 方案 C（本次新增建议）：把默认后端切回 hybrid

hybrid 已实现（BM25 优先 + 向量补位，RRF 融合），离线实测覆盖 **98.5%**，是三种后端里唯一覆盖 BM25 全部命中的方案。

| 维度 | 评估 |
|---|---|
| 能修 | G049/G052 + G021–G024（BM25 本来就能召回）+ 保留 chroma 的语义召回 |
| 不能修 | G030（选择错误，仍需 Prompt 约束） |
| 代价 | 改一个配置 `POLICY_RETRIEVER=hybrid`（可回滚）；RAG 节点延迟略升（BM25 查询为毫秒级，主要开销仍是 chroma） |
| 风险 | 融合权重/RRF 参数只有一版，需在 96 条上跑一次覆盖率对比确认无回退 |
